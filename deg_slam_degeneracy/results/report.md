# 地库 / 走廊场景退化检测实验报告

> 复现命令、目录结构见仓库根目录 `README.md`。本报告只写结论、证据与踩过的坑。

## 1. 摘要

在合成的地库（garage）、纯走廊（corridor）、玻璃幕墙（glass）三种场景上，用同一份 720 束 2D 激光 +
带 2.5% 尺度误差的轮速里程计，跑了三条管线（odom_only / naive scan-to-map / 退化感知），
并用 Cartographer（ROS 2 Humble, offline + online）作为对照。

三条结论：

1. **退化检测本身是可靠的。** 走廊场景 99.8% 帧被判定退化，条件数中位数 ~50，
   退化方向稳定落在通道轴上（实测 174.1° / 2.9° / 7.2°，与真值 180° / 0° / 0° 相差 < 10°）。
   逐帧诊断显示单帧配准完全健康（rmse 中位 0.03 m、inlier 中位 0.76），
   漂移是"每帧都没错但每帧都差一点"的累积，不是某帧崩飞。

2. **"检测到退化 → 锚定里程计"只在特定条件下有效。** 玻璃墙 + 8 m 量程：4.754 → 1.292 m（−73%）；
   纯走廊 + 8 m 量程：4.787 → 5.560 m（+16%，更差）。差别在于里程计误差是否被放大成系统性偏置。

3. **玻璃/无回波表面是最坏的情况。** 玻璃墙 + 20 m 量程 ATE 16.81 m（接近"闭眼走"），
   因为只剩单侧墙，横向自由度完全不可观测，且远距噪声点让匹配"自信地错"。

### 2.2 读表要点

- **garage**：scan matching 稳定优于里程计 3 倍（2.72 → 0.91 m）。退化判据一次未触发，
  说明"边长通道 + 立柱/车位缺口"的地库并不必然退化——**条件数高 ≠ 不可观测**。
- **corridor**：判据几乎全程报警，方向始终沿 x 轴。20 m 量程时仍能吃到 20 m 外的前后墙端，
  所以只漂 1.33 m；8 m 量程连墙端都看不到，漂到 4.8 m。**量程决定走廊的可观测性**，
  这条对选型（20 m vs 8 m 激光）是有直接价值的结论。
- **glass**：20 m 场景只剩一侧墙，横向不可观测，退化方向翻到 96°（垂直于行进方向），
  ATE 16.8 m。8 m 量程把远处噪声砍掉后，近处地面/车位结构让软先验真正生效，**−73%**。
  → 玻璃幕墙前宁可用短量程取干净近点，也不要拿远距噪声点当约束。
- **deg_aware 不是万灵药**：corridor_r8 触发 6 帧却更差。锚定的参考值是里程计，
  里程计带 2.5% 尺度误差，方向对、参考值错，锚得越紧偏置越实。

### 2.3 与 Cartographer 的对照

在同一份 rosbag2（720 束 / 360° / 5 Hz / 500 帧 / 约 104 m 往返）上跑 Cartographer（ROS 2 Humble，offline node）：

| 配置 | 结果 |
| --- | --- |
| 纯激光（`use_odometry=false`） | 节点与地图流程正常，但**位姿不推进**：所有扫描叠在起点，地图呈放射状扇形，覆盖范围只有一个量程（±20 m） |
| 提供里程计（`use_odometry=true`，2% 尺度误差 + 0.03°/s 偏航） | 位姿开始推进、submap 正常插入（`Inserted submap (0,0)…(0,n)`），但轨迹在直道上偏转约 45°，地图与真值不重合 |

产物：`results/cartographer/garage_r20/{map.pgm, map.yaml, trajectory.pbstream, offline.log}`。

**这两条都是结论，不是 bug 掩盖：**

1. 无外部位姿先验时，Cartographer 在平行通道里连"前进"都估计不出来——轴向梯度为零（与本文 §2.1 走廊 99.8% 帧退化一致）。
   这直接说明**为什么地库移动充电小车必须有轮速/IMU 里程计**，不能指望纯激光推算位移。
2. 给定里程计后能推进，但因**扫描格式是 360° 全向**（Cartographer 2D 的典型输入是 270° 单线雷达），
   加上无 IMU 做重力/角速度约束，yaw 在转弯段被估错，整段地图旋转。
   真实平台通常用 270° 雷达 + IMU，或用 `num_subdivisions_per_laser_scan` 做运动畸变补偿。

对照的意义在于：**本仓库的无回环前端虽然也会漂，但至少位姿连续、方向正确**；
Cartographer 在输入与假设不匹配时会更极端。这也是"跑通 ≠ 跑对"的一个实例。

## 3. 失败案例与踩坑（按价值排序）

1. **瞬时掉头的真值轨迹是错的。** 最初轨迹在折返点把 yaw 从 0 直接跳到 π，
   360° 激光会认为"倒着走的扫描"同样匹配，位姿被翻面，ATE 直接崩到 9 m。
   改成半径 1 m 的半圆 U 型转弯后恢复正常。**真实底盘不可能瞬间转向，仿真也别偷懒。**
2. **滑窗局部地图会放大漂移。** 为抑制漂移给 `MapModel` 加了 16 m 滑窗，结果玻璃场景 ATE
   从 2 m 涨到 35 m：窗口跟着错误位姿一起移动，误差自我强化。回退到累积地图 + 故障保护才对。
3. **故障保护（fail-safe）是必需的。** inlier < 0.35 或 rmse > 0.25 m 时直接回退里程计先验，
   纯走廊 ATE 从 8.93 m 降到 1.33 m。工程上"这一帧不信激光"比"硬解"划算得多。
4. **软先验的符号。** 最初写成 `−b − λV(Vᵀ(x_odom−x))`，退化方向被推向里程计的反方向，ATE 2.3 m。
   正确形式是 `Δ = (H + λVVᵀ)⁻¹(−b + λV(Vᵀ(x_odom−x)))`。
5. **不要对 3×3 Hessian 整体做退化锚定。** 最小特征向量会把 θ 一起锚到漂移的偏航
   （yaw 零偏 0.25 °/s × 102 s ≈ 25°），轨迹整体被拉歪。只对**平移 2×2 子块**做。
6. **Cartographer 的两种 node 参数风格不同，且单复数不一样。**
   `cartographer_offline_node`：gflags `-configuration_directory`、**`-configuration_basenames`（复数）**、
   `-bag_filenames`、`-save_state_filename`；写成 `-p` 会报 `RCLInvalidROSArgsError`。
   `cartographer_node`：gflags `-configuration_basename`（**单数**），且经 `ros2 run` 会被当成未知 ROS 参数，
   必须直调 `/opt/ros/humble/lib/cartographer_ros/cartographer_node`。
7. **lua 沙箱没有 `math.radians`**，配置里必须写数值（`0.5° = 0.0087266`）。
8. **rosbag2 要求目标目录不存在。** 预先 `makedirs` 会报 `Database directory already exists`，
   要让 rosbag2 自己建目录。
9. **`LaserScan` 的 `angle_max` 必须满足 `angle_min + increment*(n-1)`**，写成 `+π` 会差一个 increment，
   虽然本实验里不改也照样跑（Cartographer 未拒帧），但这是所有下游工具都会踩的格式坑。
10. **360° 全向 LaserScan 不是 Cartographer 2D 的舒适区**：没有 IMU、扫描含正后方点，
    转弯段的 yaw 会被估错，整张地图旋转（见 §2.3）。

## 4. 对岗位的直接映射

| JD 要求 | 本仓库覆盖 | 边界 |
| --- | --- | --- |
| 精准定位（激光 SLAM / 融合定位） | ✅ 2D 激光 scan-to-map + 退化检测 + 软先验 | 未做视觉/IMU 融合，未做 3D |
| 复杂地库环境适应性 | ✅ 立柱、车位缺口、玻璃幕墙、量程敏感性 | 无动态障碍（行人/车辆） |
| 测试方案与数据分析 | ✅ 逐帧指标（cond/inlier/rmse/方向）、ATE/RPE、失败复盘 | 无实车 |
| 越障 / 位姿调整 / 底盘适配 | ❌ 本仓库不涉及 | 需另做运动学与执行器标定实验 |
| 硬件选型 | 间接：证明量程 20 m 与 8 m 对走廊可观测性的影响 | 未做多传感器标定 |

## 5. 下一步

1. **加绝对锚点实验**：在走廊每 12 m 布设一个反光柱/二维码观测（σ=2 cm），
   验证"锚点把长通道漂移压到 < 0.3 m"的假设——这是本报告结论的自然延伸。
2. **把前端升级为 scan-to-submap + 回环**，与 Cartographer 公平对比同架构下的退化处理收益。
3. **接真实数据**：地库实车 rosbag（若有），或用 3D 激光 + IMU 跑 FAST-LIO2，
   在退化场景下检查其 Hessian 条件数与本文结论是否一致。
4. **动态障碍**：加入随机行人/车辆，检验 fail-safe 阈值在真实噪声下的鲁棒性。
