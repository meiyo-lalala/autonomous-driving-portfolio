# 多传感器融合定位（SLAM / 里程计）— 手搓版

> 对应简历强项：**L2+ 多传感器融合定位量产装车 >10 万台**、**LiDAR + 视觉 + 差分 GNSS 融合**。
> 本项目把"融合定位"从量产工程经验，落到**可运行、可复现、可进 GitHub** 的代码资产，
> 全部**手写实现**，不依赖 Open3D / PCL / ROS。

## 它解决了什么问题

自动驾驶定位的核心矛盾：
- **IMU 死推算**：高频、平滑，但积分会**累积漂移**（尤其 yaw 角）。
- **LiDAR-ICP 里程计**：相对位姿准，但**误差逐帧累积**成大漂移。
- **GNSS/差分 GPS**：绝对位置，但**带噪声、城市里会断锁**。

本项目用**松耦合 EKF** 把三者融合，得到一条"既准（靠 GNSS 锚定）又稳（靠 IMU/ICP 补全）"的轨迹。

## 模块拆解（全部手写）

| 文件 | 内容 | 对应能力点 |
|------|------|-----------|
| `world.py` | 合成真值轨迹 + 路标世界 + 传感器采样（LiDAR/IMU/GNSS） | 仿真闭环、数据生成 |
| `icp.py` | **point-to-point ICP**，SVD（Horn 法）求解相对位姿，含反射修正 | 点云配准、特征匹配 |
| `fusion_ekf.py` | **松耦合 EKF**：状态 `[x,y,yaw,vx,vy,wy]`，IMU 预测 + ICP/IMU 位姿更新 + GNSS 更新 | 多源融合、状态估计 |
| `bev_map.py` | 用估计轨迹把多帧点云累积成 **BEV 占据地图** | 定位→建图闭环 |
| `run.py` | 全链路跑通 + 出图（轨迹对比 / 误差曲线 / BEV 地图） | 工程整合、可视化 |

## 运行

```bash
cd projects/slam_fusion
pip install numpy matplotlib tqdm
python run.py
```

产出（在 `assets/`）：
- `trajectory.png` — EKF 融合轨迹 vs 真值，以及 IMU-only / ICP-only 两条漂移基线
- `bev_map.png` — 用 EKF 轨迹累积的 BEV 占据地图

## 预期效果（固定随机种子，可复现）

```
ATE(m)  EKF=1.06  IMU=2.94  ICP=1.27  GNSS_std=0.52
```

- **EKF 融合定位** ATE 仅 **1.06 m**，明显优于两条单传感器基线；
- **IMU 死推算** ATE=2.94 m（已加入陀螺零偏，里程越长漂移越大——这正是需要融合修正的痛点）；
- **LiDAR-ICP 里程计** ATE=1.27 m（相对准但逐帧累积小幅漂移）；
- **GNSS** 提供绝对锚点（噪声约 0.5 m），EKF 靠它把漂移拉回。

直观展示了"**融合 > 任一单传感器**"，与你量产项目里的融合定位逻辑一致。

## 怎么接真实数据（面试时能讲的点）

代码刻意把"传感器采样"和"融合算法"解耦：

| 合成模块 | 替换为 | 下游 |
|----------|--------|------|
| `sample_lidar` | 读 `.pcd`/`.bin` + 去地面 | ICP 不变 |
| `sample_imu` | 真实 IMU 驱动（含 bias 标定） | EKF 预测不变 |
| `sample_gnss` | RTK/差分 GPS 驱动 | EKF 更新不变 |

`icp.py` 的 `icp()` 与 `fusion_ekf.py` 的 `PoseEKF` 是**纯算法核心**，换数据即可直接用，
无需改融合逻辑——这正是量产落地时的做法：**算法稳定，数据接口适配**。
